# રિમોટ વિડિયો કંટ્રોલ (Remote Video Control)

એક **નવા Android ફોન** વડે બીજા ફોનમાં વિડિયો ચલાવો અને તેને કંટ્રોલ કરો.

- 🎮 **નવો ફોન = કંટ્રોલર** → ફક્ત **બટન** (Play/Pause, Next, Seek, Volume). અહીં વિડિયો ચાલતો નથી.
- 🎬 **જૂનો ફોન = પ્લેયર** → તેના browser માં **મોટી સ્ક્રીનમાં વિડિયો** ચાલે છે.

> કોઈ server ની જરૂર નથી! બન્ને ફોન સીધા એકબીજા સાથે જોડાય છે (WebRTC / PeerJS).
> **વિડિયો ક્યાંય અપલોડ કરવાનો નથી** — નવા ફોનની ગેલેરીમાંથી પસંદ કરો, એટલે તે સીધો જૂના ફોનમાં જાય છે.
> GitHub Pages પર host કરવા માટે બનાવેલું છે — ફક્ત આ files:

- `index.html` — મુખ્ય પેજ (રૂમ કોડ બનાવો / જોડાઓ)
- `player.html` — જૂના ફોન માટે પ્લેયર (વિડિયો ચાલે છે)
- `controller.html` — નવા ફોન માટે કંટ્રોલર (ફક્ત બટન + વિડિયો પસંદ કરવાનું બટન)
- `transfer.js` — ફોનથી ફોન વિડિયો મોકલવાનો કોડ (બન્ને પેજ વાપરે છે)

## GitHub Pages પર host કરવું (એક વાર)

1. આ repo ને GitHub પર push કરો.
2. **Settings → Pages → Branch** = `main` → folder = `/ (root)` → **Save**.
3. તમને લિંક મળશે, જેમ કે `https://USER.github.io/REPO/`.
4. બન્ને ફોનમાં આ લિંક ખોલો.

## વપરાશ (Usage)

1. કોઈ પણ ફોનમાં લિંક ખોલો → **"નવો રૂમ કોડ બનાવો"** → 4 આંકડાનો કોડ.
2. **જૂના ફોન**માં → **"હું જૂનો ફોન છું" (Player)** → એ જ કોડ → **▶ શરૂ કરો** (ફુલસ્ક્રીન).
3. **નવા ફોન**માં → **"હું નવો ફોન છું" (Controller)** → એ જ કોડ.
4. નવા ફોનમાં લીલું બટન **"📂 આ ફોનમાંથી વિડિયો પસંદ કરો"** દબાવો → ગેલેરી/ફાઇલમાંથી વિડિયો પસંદ કરો
   (એકસાથે ઘણા પણ પસંદ કરી શકાય).
5. વિડિયો આપમેળે જૂના ફોનમાં મોકલાય છે (બન્ને ફોનમાં % દેખાશે) અને પૂરો થતાં જ ત્યાં ચાલવા લાગે છે.
   પછી Play/Pause/Next/Seek બટનથી કંટ્રોલ કરો.

> 💡 જૂના ફોનમાં **Chrome** browser વાપરો (WebRTC માટે). બન્ને ફોન **સમાન Wi-Fi** પર હોય તો વિડિયો ઝડપથી જાય છે
> (Wi‑Fi પર ~1 GB ની ફિલ્મ થોડી મિનિટોમાં); મોબાઇલ ડેટા/ઇન્ટરનેટ પર પણ ચાલે છે પણ ધીમું રહેશે.
>
> 💡 વિડિયો મોકલાતો હોય ત્યારે બન્ને ફોનમાં આ પેજ **ખુલ્લું રાખો** (સ્ક્રીન બંધ ન કરો).
> જૂના ફોનમાં વિડિયો ફક્ત યાદશક્તિમાં રહે છે — પેજ બંધ થાય તો કંટ્રોલર તેને આપમેળે ફરી મોકલે છે.

## શું શું કરી શકાય

- 📂 નવા ફોનની **ગેલેરી/ફાઇલમાંથી વિડિયો પસંદ** કરીને જૂના ફોનમાં ચલાવવો (કોઈ અપલોડ/લિંક નહીં)
- ▶ / ⏸ Play–Pause
- ⏮ Previous / ⏭ Next (પ્લેલિસ્ટમાં)
- ⏩ Seek (વિડિયોમાં આગળ-પાછળ)
- 🔊 Volume + 🔇 Mute
- 📋 પ્લેલિસ્ટમાંથી કોઈ પણ વિડિયો પસંદ કરવો / કાઢી નાખવો
- 🔗 (વધુ વિકલ્પોમાં) ઇન્ટરનેટ પરની સીધી MP4 લિંક ચલાવવી / ડેમો વિડિયો

## વિડિયો ફોર્મેટ

જૂનો ફોન જે ફોર્મેટ ચલાવી શકે તે જ ચાલશે. **MP4 (H.264 + AAC)** સૌથી સલામત છે — ફોનના કૅમેરાના વિડિયો
અને WhatsApp ના વિડિયો સામાન્ય રીતે આ જ હોય છે. MKV / AVI / HEVC (H.265) જૂના Android ના Chrome માં કદાચ ન ચાલે;
તો પ્લેયરમાં "આ વિડિયો ચાલી શકતો નથી" દેખાશે.

## ટેકનિકલ નોંધ

આ **screen mirroring** નથી — પરંતુ તમારા કહ્યા મુજબ **"વિડિયો મોડ"** છે: કંટ્રોલર ફોનમાં ફક્ત બટન, અને પ્લેયર ફોનમાં વિડિયો.

- પસંદ કરેલી વિડિયો ફાઇલ કંટ્રોલરથી પ્લેયર સુધી **એ જ WebRTC data connection** પરથી 16 KB ના ટુકડામાં જાય છે
  (`transfer.js`) — કોઈ upload server કે cloud storage નથી; ફાઇલ ફોન બહાર ક્યાંય જતી નથી (PeerJS server ફક્ત
  કનેક્શન જોડવા માટે વપરાય છે).
- પ્લેયર ટુકડા ભેગા કરી `Blob` બનાવે છે અને `<video>` માં object URL થી ચલાવે છે; આખો વિડિયો RAM માં એકસાથે
  રાખવાને બદલે દર 4 MB એ Blob માં ફેરવાય છે, જેથી જૂના ઓછી RAM વાળા ફોન પણ મોટા વિડિયો લઈ શકે.
- મોકલતી વખતે `bufferedAmount` જોઈને back-pressure રખાય છે, એટલે કનેક્શન તૂટતું નથી; પ્લેયર દર ~300 ms એ
  કેટલું મળ્યું તે પાછું જણાવે છે (તેના પરથી % અને બાકી સમય દેખાય છે).
- કનેક્શન તૂટે તો કંટ્રોલર આપમેળે ફરી જોડાય છે અને અધૂરો વિડિયો ફરી મોકલે છે.

**સ્થાનિક રીતે ચલાવવા** (વૈકલ્પિક): `python3 -m http.server 8080` પછી બ્રાઉઝરમાં `http://localhost:8080`.
